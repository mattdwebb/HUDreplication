# HUDreplication

This repository provides the code required to replicate an upcoming comment which itself replicates Christensen and Timmins' 2022 JPE paper, "Sorting or Steering: The Effects of Housing Discrimination on Neighborhood Choice". In addition, the repository and comment correct several coding and data cleaning errors, and use a reconstructed-sample specification to reanalyze the same questions from the original paper. The original paper measures the degree of discrimination that people of color face in the housing market.

The repository has two major sections:

1. `ct_sample`: replication of the Christensen and Timmins (2022) analysis, starting from their replication files, with corrections to a number of data cleaning errors and several approaches to generating fixed effects for the geographical region of recommended houses.
2. `reconstructed_sample`: a new specification that is appropriate for the paired testing design of the 2012 Housing Discrimination Study (HDS 2012). This section works directly from the raw data of HDS 2012 with no inputs from the C&T2022 replication package.

The repository is organized so that raw or source inputs live in `Data`, C&T-sample intermediates live in `Data/Generated/ct_sample`, reconstructed-sample intermediates live in `Data/Generated/reconstructed_sample`, and final output tables are written inside the corresponding folder for each analysis approach.

## Data Layout

Data files are not stored in Git, except for `Data/meta_comparison.csv`. A replication bundle should include `Data/HUDreplication_data.zip`; unzip it into `Data` before running the workflows. After unzipping, the following source-data folders should exist:

`Data/CT2022_Replication_Data`
- Christensen and Timmins replication inputs used by the C&T-sample workflow.
- Includes:
  - `adsprocessed_JPE_censor.rds`
  - `HUDprocessed_JPE_census_042021.rds`
  - `HUDprocessed_JPE_names_042021.rds`
  - `HUDprocessed_JPE_testscores_042021.rds`
  - `HUDprocessed_tract.rds`
  - `recsprocessed_JPE.rds`
  - `tester_assignment.csv`
  - `zipinfo.dta`
  - `zipinfo-county.dta`

`Data/HDS2012_Raw_Data`
- HDS raw SAS files used by the reconstructed-sample workflow
- Required files:
  - `assignment.sas7bdat`
  - `rechomes.sas7bdat`
  - `rhgeo.sas7bdat`
  - `sales.sas7bdat`
  - `taf.sas7bdat`
  - `tester_public.sas7bdat`

`Data/Non_HDS_Data`
- External non-HDS inputs used by the reconstructed-sample workflow
- Includes school-boundary, SEDA, Superfund, PM2.5, and RSEI inputs

`Data/meta_comparison.csv`
- Input for the C&T-sample meta-analysis figure.

`Data/Generated`
- Shared generated-data root. These files are generated by the scripts and are ignored by Git.
- Includes:
  - `ct_sample`
  - `reconstructed_sample`
  - `Intersection Files`

## Software

- R
- Stata
- LaTeX, only if compiling the formatted-table preview PDF
- Internet access for:
  - `tigris` downloads in C&T-sample preprocessing
  - `tidycensus` ACS pulls in reconstructed-sample cleaning
  - geocoding APIs in reconstructed-sample cleaning
  - Stata SSC package installs in C&T-sample analysis

The Stata driver installs missing SSC packages automatically. Some R helper scripts install missing packages, but a clean replication machine should have the main R dependencies available before running: `dplyr`, `readr`, `haven`, `stringr`, `tidyr`, `purrr`, `readxl`, `sf`, `tigris`, `lfe`, `broom`, `xtable`, `httr`, `jsonlite`, `tibble`, `tidygeocoder`, `tidycensus`, `data.table`, `RANN`, `foreign`, and either `hdf5r` or `rhdf5` for HDF5 PM2.5 inputs. The reconstructed-sample ACS step requires a valid Census API key.

## One-Time Setup

Set the repository root path in the two C&T-sample drivers before running:

- `ct_sample/main.do`
- `ct_sample/preprocess_place_city_dedup.R`

The reconstructed-sample R scripts infer the repository root when run from either the repository root or `reconstructed_sample`.

For the reconstructed-sample workflow, `reconstructed_sample/api_keys.R` must exist and contain a valid `CENSUS_API_KEY`. A template is provided at `reconstructed_sample/api_keys_template.R`.

`ct_sample/main.do` currently sets `global FORCE_CLEAN 1`, which rebuilds cleaned Stata inputs from the current generated CSV files on each run. Set it to `0` only if you intentionally want to reuse existing cleaned `.dta` files in the relevant `ct_sample/Output` subfolders.

## C&T-Sample Workflow

### Step 1: Build corrected C&T-sample inputs

Run:

- `Rscript ct_sample/preprocess_place_city_dedup.R`

This script reads the source C\&T inputs from `Data/CT2022_Replication_Data` and writes `.rds`, `.csv`, and `.dta` versions of the corrected-city C&T-sample outputs (both `_processed` and `_with_duplicates`) for:

- `adsprocessed`
- `HUDprocessed_census`
- `HUDprocessed_names`
- `HUDprocessed_testscores`

It also writes:

- C&T-sample intermediates to `Data/Generated/ct_sample`
- logs (`dedup_log_processed.csv` and `dedup_log_with_duplicates.csv`) inside `Data/Generated/ct_sample`
- cached spatial intersection files in `Data/Generated/Intersection Files`

The first run can take a long time because it builds and caches state-level spatial intersections.

The `_processed` files are the default C&T-sample analysis inputs. The `_with_duplicates` files preserve duplicates and are used only for the original-data comparison-table columns.

### Step 2: Run C&T-sample Stata analysis

Open Stata and run:

- `ct_sample/main.do`

This script runs:

- `comparison_tables.do`
- `appendix_tables.do`

C&T-sample outputs are written to:

- `ct_sample/Output/comparison_table_estimates`
- `ct_sample/Output/corrected`
- `ct_sample/Output/original`

The meta-analysis figure script is separate. After setting the repository root in `ct_sample/main.do`, run `do "${CODE}/meta_analysis.do"` from Stata if the meta-analysis figure needs to be regenerated. This writes `meta_analysis_p_values.pdf` and `meta_analysis_p_values.png` to `ct_sample/Output`.

### Optional: market-clustered C&T-sample tables

To regenerate the C&T-sample tables with standard errors clustered at the market level rather than the trial level, run:

- `ct_sample/market_clustered_tables.do`

This driver re-runs the C&T-sample comparison tables and both sets of full appendix tables using the same point-estimate specifications as the trial-clustered C&T-sample analysis, changing only the clustering level. Outputs are written to:

- `ct_sample/Output/market_clustered/comparison_table_estimates`
- `ct_sample/Output/market_clustered/corrected`
- `ct_sample/Output/market_clustered/original`

## Reconstructed-Sample Workflow

### Step 1: Clean and merge reconstructed-sample data

Run:

- `Rscript reconstructed_sample/data_cleaning.R`

This script reads the HDS raw files from `Data/HDS2012_Raw_Data`, performs the internal merges and cleaning, geocodes recommended properties, pulls ACS data, merges the external datasets, and writes reconstructed-sample intermediates to `Data/Generated/reconstructed_sample`. This script takes about 30 minutes to run on a M1 Macbook Pro, with the majority of the time spent in geocoding particularly the address-by-address fallback geocoding methods. 

Key outputs include:

- `Data/Generated/reconstructed_sample/sales_cleaned.csv`
- `Data/Generated/reconstructed_sample/sales_and_tester_merged.csv`
- `Data/Generated/reconstructed_sample/sales_and_tester_appointments.csv`
- `Data/Generated/reconstructed_sample/sales_tester_rechomes_merged.csv`
- `Data/Generated/reconstructed_sample/sales_tester_rechomes_geocoded.csv`
- `Data/Generated/reconstructed_sample/cleaned_hds.csv`

If `Data/Generated/reconstructed_sample/sales_tester_rechomes_geocoded.csv` already exists and you want to skip the geocoding step, rerun with:

- `Rscript reconstructed_sample/data_cleaning.R --skip-geocoding`

### Optional: regenerate methodology appendix diagnostics

To recreate the validation tables used in the data-cleaning methodology appendix, run:

- `Rscript reconstructed_sample/matching_diagnosis.R`

This script reads the reconstructed-sample generated files from `Data/Generated/reconstructed_sample`, the Christensen and Timmins replication files from `Data/CT2022_Replication_Data`, and external inputs from `Data/Non_HDS_Data`. It writes full LaTeX tables to:

- `reconstructed_sample/Appendix_Tables`

It also writes detailed validation CSVs to:

- `Data/Generated/reconstructed_sample`

Both output locations are ignored by Git. If running the script from another working directory, pass the repository root explicitly:

- `Rscript reconstructed_sample/matching_diagnosis.R --repo-root=/path/to/HUDreplication`

To write the LaTeX tables somewhere other than `reconstructed_sample/Appendix_Tables`, pass:

- `Rscript reconstructed_sample/matching_diagnosis.R --output-dir=/path/to/output_directory`

### Step 2: Run reconstructed-sample analysis

Run:

- `Rscript reconstructed_sample/analysis.R`

This script reads the reconstructed-sample cleaned data from `Data/Generated/reconstructed_sample` and writes outputs to:

- `reconstructed_sample/Tables`
- `reconstructed_sample/Appendix_Tables`

### Step 3: Generate formatted LaTeX tables

Run:

- `Rscript reconstructed_sample/format_tables.R`

This script reads the main reconstructed-sample LaTeX outputs from `reconstructed_sample/Tables` and writes cleaned presentation versions to:

- `reconstructed_sample/Tables/Formatted_Tables`

The formatted outputs include:

- single-table versions of Tables 5, 6, 7, and 12
- combined panel versions of Tables 8, 9, and 10
- the original Christensen and Timmins table number as a subtitle in each formatted caption
- a preview wrapper document at `reconstructed_sample/Tables/Formatted_Tables/formatted_tables_preview.tex`

To compile the preview PDF, run:

- `cd reconstructed_sample/Tables/Formatted_Tables`
- `pdflatex -interaction=nonstopmode -halt-on-error formatted_tables_preview.tex`

This writes:

- `reconstructed_sample/Tables/Formatted_Tables/formatted_tables_preview.pdf`

## Comparison Tables

After the C&T-sample and reconstructed-sample workflows have both been run, generate the six-column comparison tables with:

- `Rscript make_comparison_tables.R`

By default, this writes to:

- `comparison_tables`

To write the comparison tables somewhere else, pass an output directory:

- `Rscript make_comparison_tables.R /path/to/output_directory`

## Expected Execution Order

For a full clean replication from source inputs:

1. Set the repo root in the top-level scripts listed above
2. Ensure `reconstructed_sample/api_keys.R` contains a valid Census API key
3. Run `Rscript ct_sample/preprocess_place_city_dedup.R`
4. Run `ct_sample/main.do`
5. Run `Rscript reconstructed_sample/data_cleaning.R`
6. Optionally run `Rscript reconstructed_sample/matching_diagnosis.R` to regenerate methodology appendix diagnostics
7. Run `Rscript reconstructed_sample/analysis.R`
8. Run `Rscript reconstructed_sample/format_tables.R`
9. Run `Rscript make_comparison_tables.R`
