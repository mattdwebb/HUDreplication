# HUDreplication

This repository provides the code required to replicate an upcoming comment which itself replicates Christensen and Timmins' 2022 JPE paper, "Sorting or Steering: The Effects of Housing Discrimination on Neighborhood Choice". In addition, the repository and comment correct several coding and data cleaning errors, and use an all-completed-pairs specification to reanalyze the same questions from the original paper. The original paper measures the degree of discrimination that people of color face in the housing market.

The repository has two major sections:

1. `selected_sample`: replication of the Christensen and Timmins (2022) analysis, starting from their replication files, with corrections to a number of data cleaning errors and several approaches to generating fixed effects for the geographical region of recommended houses.
2. `all_completed_pairs`: a new specification that is appropriate for the paired testing design of the 2012 Housing Discrimination Study (HDS 2012). This section works directly from the raw data of HDS 2012 with no inputs from the C&T2022 replication package.

The repository is organized so that raw or source inputs live in `Data`, selected-sample intermediates live in `Data/Generated/selected_sample`, all-completed-pairs intermediates live in `Data/Generated/all_completed_pairs`, and final output tables are written inside the corresponding folder for each analysis approach.

## Data Layout

Data files are not stored in Git, except for `Data/meta_comparison.csv`. A replication bundle should include `Data/HUDreplication_data.zip`; unzip it into `Data` before running the workflows. After unzipping, the following source-data folders should exist:

`Data/CT2022_Replication_Data`
- Christensen and Timmins replication inputs used by the selected-sample workflow.
- Includes:
  - `adsprocessed_JPE_censor.rds`
  - `HUDprocessed_JPE_census_042021.rds`
  - `HUDprocessed_JPE_names_042021.rds`
  - `HUDprocessed_JPE_testscores_042021.rds`
  - `HUDprocessed_tract.rds`
  - `recsprocessed_JPE.rds`
  - `tester_assignment.csv`
  - `zipinfo.dta`
  - `zipinfo-county.dta`

`Data/HDS2012_Raw_Data`
- HDS raw SAS files used by the all-completed-pairs workflow
- Required files:
  - `assignment.sas7bdat`
  - `rechomes.sas7bdat`
  - `rhgeo.sas7bdat`
  - `sales.sas7bdat`
  - `taf.sas7bdat`
  - `tester_public.sas7bdat`

`Data/Non_HDS_Data`
- External non-HDS inputs used by the all-completed-pairs workflow
- Includes school-boundary, SEDA, Superfund, PM2.5, and RSEI inputs

`Data/meta_comparison.csv`
- Input for the selected-sample meta-analysis figure.

`Data/Generated`
- Shared generated-data root. These files are generated by the scripts and are ignored by Git.
- Includes:
  - `selected_sample`
  - `all_completed_pairs`
  - `Intersection Files`

## Software

- R
- Stata
- LaTeX, only if compiling the formatted-table preview PDF
- Internet access for:
  - `tigris` downloads in selected-sample preprocessing
  - `tidycensus` ACS pulls in all-completed-pairs cleaning
  - geocoding APIs in all-completed-pairs cleaning
  - Stata SSC package installs in selected-sample analysis

The Stata driver installs missing SSC packages automatically. Some R helper scripts install missing packages, but a clean replication machine should have the main R dependencies available before running: `dplyr`, `readr`, `haven`, `stringr`, `tidyr`, `purrr`, `readxl`, `sf`, `tigris`, `lfe`, `broom`, `xtable`, `httr`, `jsonlite`, `tibble`, `tidygeocoder`, `tidycensus`, `data.table`, `RANN`, `foreign`, and either `hdf5r` or `rhdf5` for HDF5 PM2.5 inputs. The all-completed-pairs ACS step requires a valid Census API key.

## One-Time Setup

Set the repository root path in the two selected-sample drivers before running:

- `selected_sample/main.do`
- `selected_sample/preprocess_place_city_dedup.R`

The all-completed-pairs R scripts infer the repository root when run from either the repository root or `all_completed_pairs`.

For the all-completed-pairs workflow, `all_completed_pairs/api_keys.R` must exist and contain a valid `CENSUS_API_KEY`. A template is provided at `all_completed_pairs/api_keys_template.R`.

`selected_sample/main.do` currently sets `global FORCE_CLEAN 1`, which rebuilds cleaned Stata inputs from the current generated CSV files on each run. Set it to `0` only if you intentionally want to reuse existing cleaned `.dta` files in `selected_sample/Output`.

## Selected-Sample Workflow

### Step 1: Build corrected selected-sample inputs

Run:

- `Rscript selected_sample/preprocess_place_city_dedup.R`

This script reads the source C\&T inputs from `Data/CT2022_Replication_Data` and writes `.rds`, `.csv`, and `.dta` versions of the corrected-city selected-sample outputs (both `_processed` and `_with_duplicates`) for:

- `adsprocessed`
- `HUDprocessed_census`
- `HUDprocessed_names`
- `HUDprocessed_testscores`

It also writes:

- selected-sample intermediates to `Data/Generated/selected_sample`
- logs (`dedup_log_processed.csv` and `dedup_log_with_duplicates.csv`) inside `Data/Generated/selected_sample`
- cached spatial intersection files in `Data/Generated/Intersection Files`

The first run can take a long time because it builds and caches state-level spatial intersections.

The `_processed` files are the default selected-sample analysis inputs. The `_with_duplicates` files preserve duplicates and are used only for the original-data comparison-table columns.

### Step 2: Run selected-sample Stata analysis

Open Stata and run:

- `selected_sample/main.do`

This script runs:

- `comparison_tables.do`
- `appendix_tables.do`

Selected-sample outputs are written to:

- `selected_sample/Output`

The meta-analysis figure script is separate. After setting the repository root in `selected_sample/main.do`, run `do "${CODE}/meta_analysis.do"` from Stata if the meta-analysis figure needs to be regenerated. This writes `meta_analysis_p_values.pdf` and `meta_analysis_p_values.png` to `selected_sample/Output`.

### Optional: market-clustered selected-sample tables

To regenerate the selected-sample tables with standard errors clustered at the market level rather than the trial level, run:

- `selected_sample/market_clustered_tables.do`

This driver re-runs the selected-sample comparison tables and both sets of full appendix tables using the same point-estimate specifications as the trial-clustered selected-sample analysis, changing only the clustering level. Outputs are written to:

- `selected_sample/Output/market_clustered/comparison_tables`
- `selected_sample/Output/market_clustered/corrected_full`
- `selected_sample/Output/market_clustered/original_full`
- `selected_sample/Output/market_clustered/Corrected Tables`
- `selected_sample/Output/market_clustered/Original Tables`

## All-Completed-Pairs Workflow

### Step 1: Clean and merge all-completed-pairs data

Run:

- `Rscript all_completed_pairs/data_cleaning.R`

This script reads the HDS raw files from `Data/HDS2012_Raw_Data`, performs the internal merges and cleaning, geocodes recommended properties, pulls ACS data, merges the external datasets, and writes all-completed-pairs intermediates to `Data/Generated/all_completed_pairs`. This script takes about 30 minutes to run on a M1 Macbook Pro, with the majority of the time spent in geocoding particularly the address-by-address fallback geocoding methods. 

Key outputs include:

- `Data/Generated/all_completed_pairs/sales_cleaned.csv`
- `Data/Generated/all_completed_pairs/sales_and_tester_merged.csv`
- `Data/Generated/all_completed_pairs/sales_and_tester_appointments.csv`
- `Data/Generated/all_completed_pairs/sales_tester_rechomes_merged.csv`
- `Data/Generated/all_completed_pairs/sales_tester_rechomes_geocoded.csv`
- `Data/Generated/all_completed_pairs/cleaned_hds.csv`

If `Data/Generated/all_completed_pairs/sales_tester_rechomes_geocoded.csv` already exists and you want to skip the geocoding step, rerun with:

- `Rscript all_completed_pairs/data_cleaning.R --skip-geocoding`

### Optional: regenerate methodology appendix diagnostics

To recreate the validation tables used in the data-cleaning methodology appendix, run:

- `Rscript all_completed_pairs/matching_diagnosis.R`

This script reads the all-completed-pairs generated files from `Data/Generated/all_completed_pairs`, the Christensen and Timmins replication files from `Data/CT2022_Replication_Data`, and external inputs from `Data/Non_HDS_Data`. It writes full LaTeX tables to:

- `all_completed_pairs/Appendix_Tables`

It also writes detailed validation CSVs to:

- `Data/Generated/all_completed_pairs`

Both output locations are ignored by Git. If running the script from another working directory, pass the repository root explicitly:

- `Rscript all_completed_pairs/matching_diagnosis.R --repo-root=/path/to/HUDreplication`

To write the LaTeX tables somewhere other than `all_completed_pairs/Appendix_Tables`, pass:

- `Rscript all_completed_pairs/matching_diagnosis.R --output-dir=/path/to/output_directory`

### Step 2: Run all-completed-pairs analysis

Run:

- `Rscript all_completed_pairs/analysis.R`

This script reads the all-completed-pairs cleaned data from `Data/Generated/all_completed_pairs` and writes outputs to:

- `all_completed_pairs/Tables`
- `all_completed_pairs/Appendix_Tables`

### Step 3: Generate formatted LaTeX tables

Run:

- `Rscript all_completed_pairs/format_tables.R`

This script reads the main all-completed-pairs LaTeX outputs from `all_completed_pairs/Tables` and writes cleaned presentation versions to:

- `all_completed_pairs/Tables/Formatted_Tables`

The formatted outputs include:

- single-table versions of Tables 5, 6, 7, and 12
- combined panel versions of Tables 8, 9, and 10
- the original Christensen and Timmins table number as a subtitle in each formatted caption
- a preview wrapper document at `all_completed_pairs/Tables/Formatted_Tables/formatted_tables_preview.tex`

To compile the preview PDF, run:

- `cd all_completed_pairs/Tables/Formatted_Tables`
- `pdflatex -interaction=nonstopmode -halt-on-error formatted_tables_preview.tex`

This writes:

- `all_completed_pairs/Tables/Formatted_Tables/formatted_tables_preview.pdf`

## Comparison Tables

After the selected-sample and all-completed-pairs workflows have both been run, generate the six-column comparison tables with:

- `Rscript make_comparison_tables.R`

By default, this writes to:

- `Comparison_Tables`

To write the comparison tables somewhere else, pass an output directory:

- `Rscript make_comparison_tables.R /path/to/output_directory`

## Expected Execution Order

For a full clean replication from source inputs:

1. Set the repo root in the top-level scripts listed above
2. Ensure `all_completed_pairs/api_keys.R` contains a valid Census API key
3. Run `Rscript selected_sample/preprocess_place_city_dedup.R`
4. Run `selected_sample/main.do`
5. Run `Rscript all_completed_pairs/data_cleaning.R`
6. Optionally run `Rscript all_completed_pairs/matching_diagnosis.R` to regenerate methodology appendix diagnostics
7. Run `Rscript all_completed_pairs/analysis.R`
8. Run `Rscript all_completed_pairs/format_tables.R`
9. Run `Rscript make_comparison_tables.R`
